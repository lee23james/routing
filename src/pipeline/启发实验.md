# 启发实验：过程奖励是否比结果奖励更能加速收敛

本文只保留一张主图，不再展开其他辅助图或表。实验目标是沿用现有的 `math200` 训练流程和 `math169` 跑点评测流程，对比 `TRIM-Agg` 与 `TRIM-Rubric` 的收敛速度，证明在相同训练条件下，加入过程奖励比只依赖结果奖励更能让 router 更快变好。

这里的离线 episode 文件分别是：

- 训练集：`data/episodes/math_train_200_episodes.jsonl`
- 测试集：`data/episodes/math500_episodes.jsonl`

其中 `math500_episodes.jsonl` 在当前仓库里是 169 行，对应这份实验里说的 `math169` 验证集。

## 1. 实验目标

这个实验只回答一个问题：

> 在相同训练步数下，加入过程奖励的 `TRIM-Rubric` 是否比只使用结果奖励的 `TRIM-Agg` 更快达到更高的验证准确率？

这里的“更快”指的是：

- 相同 `Router Optimization Steps` 下，`TRIM-Rubric` 的验证准确率更高
- `TRIM-Rubric` 更早进入平台期
- `TRIM-Rubric` 更早达到同一 accuracy 阈值

实验中只比较两条曲线：

- `TRIM-Agg`
- `TRIM-Rubric`

不引入 `RubricV2`，避免把“过程奖励是否有效”这个问题和“rubric 版本是否更优”混在一起。

## 2. 训练与评测设置

训练部分沿用已有的 `math200` router 训练流程，对应文件是：

- `data/episodes/math_train_200_episodes.jsonl`

- 训练集：`math200`
- 方法：`TRIM-Agg` 与 `TRIM-Rubric`
- 训练配置：保持现有 PPO 配置不变
- 对比条件：`lam`、seed、epoch 数、episodes per epoch 尽量一致

评测部分沿用 `math169` 的跑点评测流程，对应文件是：

- `data/episodes/math500_episodes.jsonl`

- 评测集：`math169`
- 评测方式：对每个保存的 checkpoint 做一次统一评测
- 评测指标：accuracy
- 评测协议：所有方法使用同一套 `math169` episodes、同一套评测代码、同一套预算规则

如果后续需要更严格地控制 compute budget，可以把 y 轴替换为“固定预算下的 accuracy”，但这份实验文档的主图先用统一 accuracy，重点只看收敛速度。

## 3. 主图设计

只画一张主图，图的定义固定为：

- Title: `Process Rewards Accelerate Router Convergence`
- x-axis: `Router Optimization Steps`
- y-axis: `MATH-169 Accuracy (%)`
- 曲线：
  - `TRIM-Agg`
  - `TRIM-Rubric`

这张图要表达的结论是：

> 在相同训练步数下，过程奖励驱动的 `TRIM-Rubric` 比只看结果奖励的 `TRIM-Agg` 更快提升验证准确率。

图中不放第二张子图，不放辅助表格，不放额外方法曲线。主图要保持干净，只让 reviewer 一眼看到“过程奖励带来更快收敛”。

## 4. 结论判定标准

如果下面这些现象同时成立，就认为实验支持目标结论：

- `TRIM-Rubric` 的 accuracy 曲线在训练早期明显高于 `TRIM-Agg`
- `TRIM-Rubric` 更早到达同一个 accuracy 水平
- `TRIM-Rubric` 的上升斜率更大，平台期更早出现

如果图上两条曲线差距不够明显，先不要改图形叙事，优先回到训练超参里检查：

- `lam` 是否偏小或偏大
- `lam_rubric` 是否合适
- 是否需要换一个更合适的 checkpoint 间隔来观察早期收敛

但无论如何，最终文档里只保留这一张主图，不再增加第二张补充图来分散重点。

## 5. 图注建议

建议图注写成一句话：

> 在统一的 `math169` 验证协议下，加入过程奖励的 `TRIM-Rubric` 比只依赖结果奖励的 `TRIM-Agg` 更快提升 router 的验证准确率，说明过程奖励比结果奖励更能加速收敛。

## 6. 这份实验的边界

这份实验只回答“收敛速度”这个问题，不试图同时证明：

- 最终 accuracy 一定更高
- compute cost 一定更低
- rubric 权重一定更优

这些都可以作为后续扩展，但不放进这次的主图里。
